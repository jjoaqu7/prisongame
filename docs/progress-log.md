- Five parallel researchers wrote notes under `docs/research/research_notes/Unity first person melee combat/`: design references, Unity implementation, NPC combat AI, architecture and testing (including co-op readiness), and production pipeline (animation, audio, Steam). The production researcher stopped on a usage limit while revising one claim. Its notes were inspected and are complete; the claim in question (Steam's waiting period, 21 versus 30 days) is already marked unverified in them.
- A report writer merged the notes into [the report](research/reports/Unity%20first%20person%20melee%20combat.md) (about 145 cited sources). The primary agent read it in full and checked that recommendations are labelled Proposed, user decisions Open, and only recorded decisions Agreed. It proposes one approach, a type table, an assembly-definition layout, a test plan and an eight-step build order for ENCOUNTER-01, and ends with 13 open decisions. Decisions 1 (what a weapon changes), 4 (what zero health does) and 5 (what happens when the player loses) block the most code.
- The report argues against the literal reading that an armed player stops the inmate fighting back (no reference does this, and nearby weapons would end the fight at the first pickup). That is a recommendation for the user to accept or reject.
- Known weak spots, stated in the report: many mechanics details come from fan wikis or search excerpts; no sourced first-person hitstop or input-buffer timings; `Physics.autoSyncTransforms` status in 6.3 unconfirmed; Australian classification for a Steam-only game unresolved; whether the Asset Store's AI-input clause covers coding agents reading purchased files is untested.
- No game code, scenes or builds changed.
